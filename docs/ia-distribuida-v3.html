La métrica Ω

Esto es lo que distingue una respuesta confiable de una que no lo es. Nada más.

Ω = similitud coseno entre embeddings de A y B Los embeddings los genera un modelo de sentence‑transformers (paraphrase‑multilingual‑MiniLM‑L12‑v2), entrenado específicamente para determinar si dos textos son equivalentes en significado. AUC validado: 0.9539 sobre pares de Wikipedia. Coherentes mu=0.433 · Divergentes mu=0.064 · Separación=0.369

Se iniciaron pruebas con NLI (DeBERTa, BART) para detectar argumentos opuestos, pero se dejaron sin terminar porque los embeddings multilingües resolvieron el problema con un AUC de 0.9539. Esas pruebas no forman parte del resultado final ni del paper.

📄 Paper disponible. La validación experimental completa está documentada en Semantic Coherence Verification for Distributed AI Inference (Preprint, Mayo 2026). AUC 0.9539 sobre 1,000 pares reales de Wikipedia en español. Disponible en el repositorio.

Middleware sobre Exo

Exo se encarga de repartir las capas del modelo entre dispositivos. La idea es poner una capa encima que verifique cada respuesta antes de entregarla al usuario.

El código de abajo es un borrador para ilustrar la idea. No está probado en producción. El umbral concreto se calibrará cuando tengamos los cuatro subgrupos (A/B/C/D) evaluados.

# middleware_omega.py — borrador conceptual, no probado from sentence_transformers import SentenceTransformer model = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2') def verificar_respuesta(respuesta_nodo, respuesta_referencia): emb_a = model.encode(respuesta_nodo, convert_to_tensor=True) emb_b = model.encode(respuesta_referencia, convert_to_tensor=True) omega = float(np.dot(emb_a, emb_b) / (np.linalg.norm(emb_a) * np.linalg.norm(emb_b))) return omega # el umbral se calibrará por dominio y subgrupo

Exo proporciona la velocidad. Este middleware proporciona la confianza. Lo demás es red, túneles y protocolos que ya existen.

Privacidad en capas

Un túnel VPN protege el tránsito. Pero no impide que el dueño del nodo lea lo que procesa. Para eso trabajan estas cinco capas juntas.

1. Ceguera contextual

El prompt se fragmenta y tokeniza en el cliente. Un nodo solo ve [ENT_001], nunca el dato real.

2. TEE

El fragmento se procesa dentro de un enclave cifrado. Overhead menor al 10%. Pendiente de implementación.

3. Ofuscación de salida

Los vectores se perturban con ruido diferencial. SimHash permite comparar sin ver el contenido.

4. Consenso semántico

Tres nodos procesan el mismo fragmento. Ω + quórum descartan al que diverge.

5. Honeytokens

Fragmentos trampa con resultado conocido. Si un nodo falla, se penaliza al instante.

Script ACO para MikroTik

El enrutamiento por feromonas no necesita un software aparte. Se traduce directamente a costo OSPF en RouterOS.

# Script RouterOS · ejecutar cada 60 segundos :local nodeIP "192.168.88.10" :local reputation 0.95 :local latencyMs [/ping $nodeIP count=3 avg-rtt] :local newCost (100 + ($latencyMs / 5) + ((1 - $reputation) * 1000)) /interface ospf set [find interface="ether5"] cost=$newCost

Un nodo con buena reputación y baja latencia recibe más fragmentos. Uno que falla honeytokens sube su costo automáticamente y el tráfico se va a otro lado. Como las hormigas.
